# Уязвимости сервисов: чек-лист для A/D

Формат: **Класс** — признак в коде/поведении → фикс. Самопроверка: можешь ли объяснить класс, найти его в чужом коде и пропатчить, не сломав SLA.

---

## 1. Инъекции

- **SQLi** — запрос собирается конкатенацией/f-строкой → параметризованные запросы, ORM, whitelist для имён таблиц/колонок/ORDER BY
- **NoSQLi** — JSON/объект из запроса идёт прямо в фильтр (`$ne`, `$gt`, `$where`) → приводить типы к строке, запретить операторы из пользовательского ввода
- **Command injection** — `system`, `popen`, `exec`, `shell=True`, бэктики с вводом → массив аргументов без shell, whitelist, не вызывать shell вообще
- **SSTI** — ввод попадает в шаблон как код, а не как данные (`render_template_string`, Jinja/Twig/Freemarker/Velocity) → передавать ввод только как переменную, sandbox
- **XXE** — XML-парсер с внешними сущностями/DTD → отключить DTD и external entities, использовать defusedxml
- **LDAP/XPath-инъекции** — фильтр из конкатенации → экранирование, параметризация
- **Eval injection** — `eval`, `exec`, `Function()`, `unserialize`, динамический `import` от ввода → убрать, заменить парсером/whitelist
- **CRLF / header injection** — ввод с `\r\n` попадает в заголовки/лог/почту → отсекать управляющие символы
- **Log injection** — ввод пишется в лог без санитайза (подделка записей) → экранировать переводы строк
- **Format string (в т.ч. Python `.format`/f-string от ввода)** — формат-строка контролируется пользователем → ввод только как аргумент

## 2. Аутентификация и сессии

- **Дефолтные/слабые пароли** — admin/admin, пароли в README → смена, генерация случайных
- **Захардкоженные креды и бэкдоры** — `if user == "debug"`, магические токены, скрытые эндпоинты → grep по коду на `password`, `secret`, `token`, `debug`, `admin`
- **Слабый/предсказуемый рандом** — `rand()`, `time()` как seed, `Math.random` для токенов → CSPRNG (`secrets`, `/dev/urandom`)
- **JWT** — `alg: none`, подпись не проверяется, слабый HS-секрет, путаница RS/HS, `kid` инъекция → фиксировать алгоритм, сильный секрет, проверять `exp`/`iss`
- **Session fixation** — ID сессии не меняется после логина → регенерация ID
- **Сброс пароля** — предсказуемый токен, токен не привязан к юзеру, не истекает, Host-header poisoning → случайный одноразовый токен с TTL
- **User enumeration** — разные ответы/время для «нет юзера» и «неверный пароль» → единый ответ
- **Нет rate limit на логин/OTP** — перебор → лимиты, задержки (но не банить чекер)
- **Слабая проверка 2FA** — код можно перебрать, шаг можно пропустить → привязка шага к сессии, лимит попыток
- **Cookie без флагов** — нет HttpOnly/Secure/SameSite → выставить

## 3. Авторизация (контроль доступа)

- **IDOR / BOLA** — `/note/123` отдаёт чужое, проверка только «залогинен» → проверять владельца объекта на каждом запросе
- **Missing function-level auth** — админские ручки без проверки роли, скрытые, но не защищённые → декоратор/middleware на всё
- **Privilege escalation** — роль берётся из cookie/параметра/тела запроса → роль только из серверной сессии
- **Mass assignment** — модель принимает любые поля (`is_admin`, `role`, `balance`) → whitelist полей
- **Обход по пути/методу** — защищён `/admin`, но не `/admin/`, `//admin`, другой HTTP-метод, регистр → авторизация на уровне роутера по нормализованному пути
- **Доверие клиенту** — скрытые поля, цена/ID пользователя из формы → всё пересчитывать на сервере
- **Confused deputy / вертикальные цепочки** — внутренний сервис доверяет заголовку (`X-Forwarded-For`, `X-User`) → не доверять заголовкам извне

## 4. Файлы и пути

- **Path traversal** — `open(base + user_input)`, `../` → нормализация пути + проверка, что результат внутри базовой директории
- **LFI / RFI** — `include($_GET[...])`, `require` от ввода → whitelist имён
- **Unrestricted upload** — расширение/Content-Type проверяется на клиенте или слабо → whitelist, случайное имя, хранение вне webroot, без исполнения
- **Zip slip / tar traversal** — распаковка без проверки путей внутри архива → проверять итоговые пути
- **Symlink-атаки** — следование по ссылкам в загружаемом архиве/директории → `O_NOFOLLOW`, запрет симлинков
- **Race на файлах (TOCTOU)** — проверка и использование разнесены, предсказуемые tmp-файлы → `mkstemp`, атомарные операции
- **Права на файлы** — флаги/БД читаемы всеми, 777, SUID-бинарники → минимальные права, отдельный пользователь на сервис

## 5. Десериализация

- **Python `pickle`/`yaml.load`/`marshal`** — данные от юзера → `json`, `yaml.safe_load`
- **Java `ObjectInputStream`** — gadget chains в classpath → фильтры десериализации, не принимать бинарные объекты извне
- **PHP `unserialize`** — магические методы, phar:// → JSON, `allowed_classes`
- **Node (`node-serialize`), Ruby (`Marshal`, `YAML.load`), .NET (`BinaryFormatter`)** → то же правило: не десериализовать недоверенное
- **Подписанные, но слабо защищённые объекты** — cookie-сессия с известным секретом (Flask, Rails) → сильный секрет, ротация

## 6. Веб-клиентская сторона и запросы

- **XSS (stored / reflected / DOM)** — вывод без экранирования, `innerHTML`, `|safe`, `v-html` → контекстное экранирование, CSP
- **CSRF** — состояние меняется GET'ом или POST'ом без токена → CSRF-токен, SameSite
- **SSRF** — сервер ходит по URL от юзера (превью, импорт, webhook, PDF-рендер) → whitelist хостов, запрет внутренних сетей/metadata/localhost, проверка после редиректов и DNS
- **Open redirect** — `?next=` без проверки → whitelist/относительные пути
- **CORS misconfig** — `Access-Control-Allow-Origin` отражает Origin + credentials → фиксированный список
- **Clickjacking** — нет `X-Frame-Options`/`frame-ancestors` → выставить
- **Prototype pollution (JS)** — рекурсивный merge с ключами `__proto__`, `constructor` → фильтр ключей, `Object.create(null)`
- **HTTP request smuggling** — расхождение фронта и бэка в разборе Content-Length/Transfer-Encoding → единые парсеры, обновление прокси
- **Host header injection / cache poisoning** — ссылки/кэш строятся из Host/X-Forwarded-* → фиксированный домен в конфиге
- **WebSocket без аутентификации/проверки Origin** → проверять на handshake
- **GraphQL** — introspection в проде, нет лимита глубины/батчинга, нет авторизации на поля → отключить, лимиты, проверки на резолверах
- **Parameter pollution** — дубли параметров обрабатываются по-разному → явно брать один

## 7. Бизнес-логика

- **Race condition** — двойная трата, повторное применение купона, параллельные запросы → транзакции, `SELECT … FOR UPDATE`, уникальные ограничения, атомарные операции
- **Отрицательные/нулевые/огромные значения** — перевод `-100`, количество `0` → валидация диапазонов
- **Integer overflow/precision в логике** — float для денег, переполнение счётчиков → Decimal/целые копейки
- **Обход шагов процесса** — оплата/подтверждение можно пропустить прямым запросом → серверная машина состояний
- **Повторное воспроизведение (replay)** — запрос можно переотправить → nonce/одноразовые токены
- **Неатомарные проверки** — «проверил баланс» и «списал» в разных запросах → одна транзакция

## 8. Криптография

- **ECB-режим** — одинаковые блоки дают одинаковый шифртекст → AES-GCM / ChaCha20-Poly1305
- **Повтор IV/nonce** — статичный IV, повтор nonce в CTR/GCM → случайный уникальный nonce
- **Нет аутентификации шифртекста** — CBC без MAC, malleability → AEAD
- **Padding oracle** — разные ошибки на неверный паддинг → единая ошибка, AEAD
- **Bit-flipping в CBC** — управляемая модификация расшифровки → MAC
- **Слабые хеши для паролей** — MD5/SHA1/SHA256 без соли → argon2id / bcrypt / scrypt
- **Небезопасное сравнение** — `==` для MAC/токенов (timing) → `hmac.compare_digest` и аналоги
- **Самописная криптография** — XOR-шифры, свои PRNG/хеши → стандартные библиотеки
- **Слабые параметры RSA/DH/ECC** — малый `e`, общий модуль, малые простые, повторное использование `k` в ECDSA → стандартные размеры и либы
- **Хардкод ключей** → вынос в конфиг/секрет-хранилище, ротация
- **Length extension** — `H(secret || msg)` как MAC → HMAC

## 9. Память и бинарные сервисы (pwn)

- **Stack buffer overflow** — `gets`, `strcpy`, `scanf("%s")`, `read` с неверной длиной → ограничение длины, безопасные функции, canary/NX/PIE как доп. слой
- **Heap overflow** — неверный размер `malloc`/`memcpy` → проверки границ
- **Use-after-free / double free** — указатель живёт после `free` → обнулять указатель, владение
- **Off-by-one / off-by-null** — `<=` вместо `<`, лишний `\0` → аккуратные границы
- **Format string** — `printf(user_input)` → `printf("%s", user_input)`
- **Integer overflow/underflow** — размер считается в `int`/`size_t` без проверки, signed/unsigned путаница → проверка перед использованием
- **Out-of-bounds read/write** — индекс из ввода без проверки → проверка границ
- **Type confusion** — приведение типов без проверки → проверка тега/типа
- **Uninitialized memory** — утечка данных из стека/кучи → инициализация
- **Race в многопоточности** → блокировки, атомарность
- **Включить защиты** — компиляция с `-fstack-protector`, `-D_FORTIFY_SOURCE=2`, RELRO, PIE, NX

## 10. Конфигурация и инфраструктура

- **Debug-режим в проде** — Flask `debug=True` (консоль Werkzeug), Django `DEBUG=True`, Spring actuator → выключить, закрыть
- **Открытые админки/служебные порты** — Redis, MongoDB, Memcached, Elasticsearch, Docker API, etcd без пароля → bind на localhost, auth, firewall
- **Утечка репозитория и бэкапов** — `.git/`, `.env`, `*.bak`, `*.swp`, `~`-файлы в webroot → удалить, запретить доступ
- **Directory listing** → отключить autoindex
- **Секреты в окружении/репо/образе Docker** → вынос, `.dockerignore`
- **Устаревшие зависимости с известными CVE** → обновление, `pip audit`/`npm audit`
- **Запуск от root** → отдельный пользователь, минимум прав
- **Привилегированные контейнеры, смонтированный docker.sock** → убрать
- **Небезопасные cron/sudo/SUID** — `sudo` без пароля, пишемые скрипты в cron → ревизия прав
- **Слабые права на unix-сокеты/pid/логи** → ограничить

## 11. Утечка информации

- **Подробные ошибки и stack trace** → generic-ответы, логи на сервере
- **Утечка в API** — лишние поля в JSON (хеши, токены, чужие данные) → DTO/сериализаторы с whitelist
- **Комментарии, source maps, `robots.txt`, `/server-status`, `/metrics`** → закрыть
- **Timing/size side-channels** → одинаковое время/размер ответа там, где это критично
- **Различие ответов (oracle)** — по ответу можно узнать скрытое состояние → унифицировать

## 12. Отказ в обслуживании и ресурсы

- **ReDoS** — вложенные квантификаторы в регулярках → простые regex, лимиты, RE2
- **Zip/XML bombs (billion laughs)** → лимиты размера и вложенности
- **Неограниченный ввод** — тело запроса, размер файла, число элементов → лимиты
- **Алгоритмическая сложность** — хеш-коллизии, квадратичные циклы по вводу → лимиты, таймауты
- **Утечка ресурсов** — незакрытые соединения/дескрипторы → пулы, таймауты

## 13. Специфика A/D

- **Где лежат флаги** — БД, файлы, память: проверь права доступа и кто может читать
- **Бэкдоры от организаторов** — уязвимости намеренно оставлены в сервисе; читай код целиком, ищи странные эндпоинты и «отладочные» проверки
- **Патч не должен ломать SLA** — чекер должен проходить; тестируй до выкладки; патчи минимальными изменениями
- **Анализ трафика (pcap / логи)** — смотри, как атакуют тебя, находи эксплойты соперников и воспроизводи их у себя
- **Не блокируй чекер** — rate limit/WAF по IP могут уронить SLA
- **Не ломай формат флагов** — фильтры на `[A-Z0-9]{31}=`-подобные паттерны легко обходятся и вредят SLA
- **Откат** — всегда храни рабочую копию и умей быстро вернуть сервис
- **Целостность файлов** — следи за изменениями в каталоге сервиса (хеши), вдруг кто-то оставил бэкдор
- **Перезапуск и автозапуск** — сервис должен подниматься сам после падения

## Самопроверка за 15 минут на новом сервисе

1. Запустить, снять карту: эндпоинты, порты, роли, где хранятся флаги
2. `grep` по рискованным функциям: `eval`, `exec`, `system`, `pickle`, `unserialize`, `open(`, `render_template_string`, `strcpy`, `gets`, `printf(`
3. Проверить авторизацию на каждом эндпоинте (кто видит чужие объекты?)
4. Проверить все места, где ввод попадает в SQL, shell, файл, шаблон, URL, парсер
5. Проверить конфиг: debug, секреты, открытые порты, права
6. Пропатчить самое дешёвое и критичное, прогнать чекер, смотреть логи/трафик
