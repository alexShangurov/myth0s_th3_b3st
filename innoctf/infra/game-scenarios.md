# 🚒 Что может случиться на игре и что делать (INNOCTF Junior, 21.11)

Ты инфраструктурщик 🏗️. Твоя работа: замок стоит, сундуки открываются, сейвы есть.
Дыры ищут и сплоиты пишут другие. Твоя цепочка: **сейв → патч → сторож**.

**Где что запускается** (запомни один раз):
| Что | Где | Почему |
|---|---|---|
| `backup.sh`, `restore.sh`, `docker compose …` | на **вулнбоксе** (по SSH) | там лежат сервисы |
| `healthcheck.sh` | на **ноуте** | ноут умеет пищать, вулнбокс нет |
| S4DFarm, Packmate, ctf_proxy-тесты | на **ноуте** (не на вулнбоксе) | так решила команда |

Обозначения: `VB` = IP вулнбокса, `~/services/<сервис>` = папка сервиса (как в `healthcheck.sh`),
`infra/` = папка со скриптами. 🎮 Раунд в ForcAD = 1 ход чекера; флаг живёт N раундов.
Точные цифры (длина раунда, жизнь флага) **уточнить у оргов** и вписать сюда: раунд = ___ с, флаг живёт ___ раундов.

## 1️⃣ До старта

### 1. Флешка не читается / файл битый / скрипт «Permission denied»
- 👀 Признаки: флешка не появилась в `/media`; `images.tar` меньше, чем дома; `./healthcheck.sh` → `Permission denied`.
- 🧯 Что делать:
  1. `ls -la /media/$USER/*` (флешка там) → `lsblk` (видит ли её система вообще).
  2. Сразу всё копируй с флешки в домашнюю папку: `cp -r /media/$USER/<флешка>/innoctf ~/`.
  3. Скрипт не запускается → запускай через bash: `bash healthcheck.sh` или верни права `chmod +x *.sh` (уже в `~`, не на флешке).
  4. Сверь размер/сумму архива с домашней: `sha256sum ~/images.tar` (сумму запиши дома заранее).
- ⚠️ Ловушка: флешка в FAT32 не хранит файлы больше 4 ГБ. Большой `images.tar` молча обрежется. Дома проверь формат (`lsblk -f`), если FAT32, то режь образы по одному файлу на тулзу.
- 🔁 Почему `./script.sh` с флешки может не запуститься, а `bash script.sh` запустится?

### 2. Нет sudo
- 👀 Признаки: `sudo` просит пароль, которого нет, или пишет «not in the sudoers file».
- 🧯 Что делать:
  1. `sudo -n true; groups`. Если в `groups` есть `docker`, Docker работает и без sudo, этого хватает.
  2. Нужен пакет (curl, openvpn) → не ставь, ищи замену: вместо `curl` есть `wget -qO-` и `python3`.
  3. Без чего не поедем (VPN, Docker) → сразу к оргам, не трать 20 минут.
- ⚠️ Ловушка: не пытайся «обойти» отсутствие прав на чужом ноуте. Это ноут оргов: спроси.
- 🔁 Какая замена `curl`, если его нет и поставить нельзя?

### 3. Docker нет или «permission denied … docker.sock»
- 👀 Признаки: `docker: command not found` или `permission denied while trying to connect to the Docker daemon socket`.
- 🧯 Что делать:
  1. `docker ps`. Ошибка сокета → `groups` (есть ли `docker`) → без sudo сам не добавишься.
  2. Иди к оргам: «на ноуте нет Docker / нет доступа к docker.sock, тулзы команды на нём».
  3. Пока ждёшь: тебе для работы с сервисами Docker на ноуте НЕ нужен, он нужен на вулнбоксе. Подключайся по SSH (карточка 6) и делай первые 5 минут (карточка 7).
- ⚠️ Ловушка: не ставь Packmate/ферму на вулнбокс «раз на ноуте нельзя». Команда решила: анализатор не на вулнбоксе. Можно ли свой ноут — **уточнить у оргов**.
- 🔁 Что важнее в первые 5 минут: Docker на ноуте или SSH на вулнбокс?

### 4. `docker load` падает
- 👀 Признаки: `no space left on device`, `unexpected EOF`, `invalid tar header`.
- 🧯 Что делать:
  1. `df -h ~` (место есть?) и `sha256sum images.tar` (сравнить с домашней суммой).
  2. `unexpected EOF` / `invalid tar header` = файл обрезан → копируй заново с флешки или грузи по одной тулзе.
  3. После загрузки: `docker images`. Теги на месте (не `<none>`)? Ты сохранял по ИМЕНАМ, значит должны быть.
  4. Образа нет → в папке тулзы `docker compose up -d` попробует собрать, а без интернета упадёт → `network-fixes.md` не поможет офлайн, нужен образ.
- ⚠️ Ловушка: не запускай `docker compose pull` без интернета: он долго висит и ничего не даст.
- 🔁 Как отличить «мало места» от «битый архив» по тексту ошибки?

### 5. ⭐ VPN не подключается
- 👀 Признаки: `ping VB` молчит; в `ip -br a` нет `tun0` / `wg0`.
- 🧯 Что делать:
  1. Посмотри, какой конфиг дали: `.ovpn` (OpenVPN) или `.conf` с `[Interface]` (WireGuard).
  2. Без sudo пробуй через NetworkManager: `nmcli connection import type openvpn file team.ovpn` (или `type wireguard file wg0.conf`) → `nmcli connection up <имя>`.
  3. Нет нужного плагина / прав → сразу к оргам.
  4. Подключился → `ip -br a` (есть туннель) → `ping -c3 VB`.
- ⚠️ Ловушка: один конфиг на двух ноутах одновременно (если он выдан на одного) может выбивать друг друга. Сколько подключений на команду, **уточнить у оргов**.
- 🔁 По какому признаку в `ip -br a` видно, что VPN поднялся?

### 6. Не пускает по SSH
- 👀 Признаки: `Permission denied (publickey)`, `Connection timed out`, `REMOTE HOST IDENTIFICATION HAS CHANGED`.
- 🧯 Что делать:
  1. `ssh -v user@VB` и читай последние строки.
  2. `timed out` → это сеть, а не SSH → карточка 5 (VPN).
  3. `publickey` → ключ: `chmod 600 ~/.ssh/id_ed25519`, `ssh -i ~/.ssh/id_ed25519 user@VB`; проверь логин (root? ubuntu?), его дают орги.
  4. `IDENTIFICATION HAS CHANGED` (вулнбокс пересоздали) → `ssh-keygen -R VB` и заново.
- ⚠️ Ловушка: не долби пароль подряд много раз. Может включиться блокировка, а сброс будут делать орги.
- 🔁 Что значит `Connection timed out`, а что `Permission denied`?

## 2️⃣ Первые 5 минут

### 7. Чек-лист «первые 5 минут» (делать по порядку)
- 👀 Признаки: игра началась, сеть открыли.
- 🧯 Что делать:
  1. `ssh VB` → `ls ~` / `docker ps -a`: какие сервисы и в каких папках.
  2. Сейв всего «как выдали»: `for d in ~/services/*/; do ./backup.sh "$d" original; done`, затем с ноута `scp -r VB:~/services ~/vb-original` (копия вне замка).
  3. На ноуте: вписать сервисы в `services.conf` (хост = `VB`, не `127.0.0.1`!) → `./healthcheck.sh --once` → `./healthcheck.sh`.
  4. В чат: список сервисов + порты + «сейвы есть». Дальше поднять ферму и Packmate.
- ⚠️ Ловушка: `backup.sh` не исключает папку `pgdata` (исключает только `data`, `db`, `*.sqlite*`). Если у сервиса БД в `pgdata/` или `mysql/`, сейв ухватит базу или упадёт на `Permission denied`. Проверь: `tar tzf <сейв>.tgz | grep -E 'pgdata|mysql'`.
- 🔁 Почему копия «как выдали» должна лежать и на ноуте, а не только на вулнбоксе?

### 8. Часть сервисов не запущена на старте
- 👀 Признаки: в `docker ps -a` статус `Exited` или `Created`; сторож показывает 💀 с первой секунды.
- 🧯 Что делать:
  1. `docker ps -a --format '{{.Names}}\t{{.Status}}'`.
  2. `cd ~/services/<сервис> && docker compose up -d` (без `--build`, код ещё не трогали).
  3. Не поднялся → `docker compose logs --tail 30`, и сразу к оргам: на старте это их зона.
- ⚠️ Ловушка: не начинай «чинить» код чужого сервиса в первые минуты. Если сервис сломан у всех, это забота оргов.
- 🔁 Зачем на старте `up -d`, а не `up -d --build`?

### 9. Сторож на ноуте видит всё DOWN / нет curl
- 👀 Признаки: `healthcheck.sh` красный по всем HTTP-сервисам, а руками в браузере всё открывается.
- 🧯 Что делать:
  1. `command -v curl nc paplay`. На стоковой Ubuntu `curl` может не быть.
  2. Без `curl` скрипт всегда видит `000` = DOWN. Проверяй вручную: `wget -qO- -T3 http://VB:5000/ | head -c 100` или `python3 -c "import urllib.request as u;print(u.urlopen('http://VB:5000/',timeout=3).status)"`.
  3. Временно убери у HTTP-сервисов путь в `services.conf` → сторож проверит хотя бы порт через `nc`.
  4. Проверь, что в `services.conf` хост = `VB`, а не `127.0.0.1`.
- ⚠️ Ловушка: `--once` берёт только `services.conf` рядом со скриптом. Свой конфиг с `--once` не сработает: правь основной.
- 🔁 Что покажет сторож, если на ноуте нет `curl`?

### 10. Кто-то ещё сидит на вулнбоксе
- 👀 Признаки: в `who` чужой IP; в `last` входы, которых не было; пароль по умолчанию одинаковый у всех.
- 🧯 Что делать:
  1. `who; last -n 10`.
  2. Если дали стандартный пароль, смени его (`passwd`), если правила это разрешают (**уточнить у оргов**). Новый пароль только в чат команды.
  3. Чужой вход → сразу оргам, со временем и IP.
- ⚠️ Ловушка: не меняй SSH-порт и не включай файрвол (`ufw`) на вулнбоксе. Чекер перестанет достучаться → DOWN на все сервисы.
- 🔁 Почему `ufw enable` на вулнбоксе может убить SLA?

## 3️⃣ Во время игры

### 11. ⭐ Сервис DOWN
- 👀 Признаки: сторож орёт 💀 и печатает подсказку; на табло DOWN.
- 🧯 Что делать:
  1. `cd ~/services/<сервис> && docker compose ps` (Up / Exited / Restarting?).
  2. `Exited` → `docker compose logs --tail 20` (подсказка сторожа) → `docker compose up -d`.
  3. Был патч только что → откат строкой ⏪ из сторожа (карточка 14).
  4. Контейнер `Up`, но снаружи не отвечает → `docker compose config | grep -A2 ports`. Если там `127.0.0.1:5000:5000`, сервис слушает только «внутри» → верни как было в оригинале.
- ⚠️ Ловушка: вердикт на табло обновится только в следующем раунде. Починил → жди раунд, не дёргай сервис снова.
- 🔁 Почему порт `127.0.0.1:5000:5000` даёт DOWN, хотя `curl localhost:5000` на вулнбоксе работает?

### 12. Сервис MUMBLE
- 👀 Признаки: сторож зелёный (порт жив), а на табло MUMBLE.
- 🧯 Что делать:
  1. Прочитай сообщение чекера на табло ForcAD (у статуса обычно есть короткий текст: что не так).
  2. Что меняли последним? Патч / фильтр → откат (карточки 14, 16).
  3. `docker compose logs --tail 50 <имя>`: ищи `Traceback`, `500`.
  4. Тормозит → карточка 22.
- ⚠️ Ловушка: MUMBLE = сервис жив, но отвечает «не так». Перезапуск не поможет: ищи, что изменилось.
- 🔁 Чем MUMBLE отличается от DOWN с точки зрения чекера?

### 13. Сервис CORRUPT
- 👀 Признаки: на табло CORRUPT: чекер не нашёл свой флаг.
- 🧯 Что делать:
  1. Вспомни: был `down`, `--build`, `restore.sh`, удаление? → `docker compose config | grep -A3 volumes`: данные в volume или внутри контейнера?
  2. Если база жива → смотри логи, ищи ошибку записи (`No space left`, `read-only`).
  3. Если флаги потерялись → назад не вернёшь. Сервис держи живым, новые флаги будут ложиться нормально.
  4. Чекер в ForcAD проверяет и **старые** флаги (за время их жизни). Поэтому CORRUPT после потери базы держится несколько раундов и сам уходит.
- ⚠️ Ловушка: не откатывай базу из сейва «original». Там нет флагов, положенных после, и CORRUPT будет дольше.
- 🔁 Почему CORRUPT держится ещё несколько раундов после того, как сервис уже починен?

### 14. ⭐ Патч сломал сервис
- 👀 Признаки: сразу после `up -d --build` сторож орёт; в логах `SyntaxError` / `ImportError` / `Traceback`.
- 🧯 Что делать:
  1. Не думать, откатывать: строка ⏪ из сторожа → `./restore.sh ~/backups/<сервис>-<время>-<заметка>.tgz ~/services/<сервис>`.
  2. `docker compose ps` + сторож зелёный.
  3. Защитнику в чат: «откатил, вот лог ошибки» (`docker compose logs --tail 20 > /tmp/err.txt`).
  4. Чинить патч он будет у себя, а не на живом сервисе.
- ⚠️ Ловушка: не откатывайся на `before-restore`: это сломанное состояние. Сторож его не предлагает специально.
- 🔁 Что лежит в сейве `before-restore` и когда он нужен?

### 15. ⭐ Пересобрал, а крутится старый код
- 👀 Признаки: в выводе сборки `CACHED [5/5] COPY . .`; дыру всё ещё эксплуатируют; поведение не изменилось.
- 🧯 Что делать:
  1. Проверь, что внутри: `docker compose exec <имя> grep -n '<строка_фикса>' /app/<файл>`.
  2. Правил не в той папке? `docker compose config | grep -A3 build` → `context:` = куда класть код.
  3. В compose `image:` без `build:` → `--build` ничего не собирает. Код в volume? Тогда хватит `docker compose restart <имя>`.
  4. Правил внутри контейнера → правка исчезнет при пересборке. Перенеси её в файл на хосте.
- ⚠️ Ловушка: `--no-cache` без интернета заново запустит `pip install` и сборка упадёт. Сначала найди причину.
- 🔁 Что значит `CACHED` у шага `COPY . .`?

### 16. После ctf_proxy / фильтра сервис стал MUMBLE
- 👀 Признаки: поставили фильтр или прокси → через раунд MUMBLE/DOWN.
- 🧯 Что делать:
  1. Сразу верни прямой путь к сервису, как было до прокси (порт снаружи = тот, что знает чекер).
  2. Подожди раунд, убедись, что OK.
  3. Защитнику: «фильтр режет чекер», пусть делает правило уже.
- ⚠️ Ловушка: не меняй внешний порт сервиса. Чекер знает только его.
- 🔁 Почему фильтр, который «режет всё подозрительное», может зарезать и чекер?

### 17. ⭐ После перезапуска пропали флаги / данные
- 👀 Признаки: после `--build` / `down` / `restore.sh` сервис пустой (нет юзеров, заметок), CORRUPT.
- 🧯 Что делать:
  1. `docker compose config | grep -A3 volumes`. Нет volume → данные жили внутри контейнера и умерли вместе с ним.
  2. Восстановить нельзя → держи сервис живым, жди (карточка 13).
  3. На будущее для этого сервиса: если volume нет, применяй патч без пересоздания: `docker cp app.py <контейнер>:/app/app.py && docker compose restart <имя>` (`restart` сохраняет файлы контейнера).
- ⚠️ Ловушка: `docker compose down -v` удаляет volumes вместе с базой. `-v` не писать никогда. `restore.sh` тоже пересоздаёт контейнер.
- 🔁 Почему `restart` не теряет данные внутри контейнера, а `up -d --build` теряет?

### 18. Контейнер в цикле рестартов
- 👀 Признаки: `docker compose ps` → `Restarting (1)`; сторож мигает UP/DOWN.
- 🧯 Что делать:
  1. `docker compose logs --tail 50 <имя>`: последняя ошибка перед падением.
  2. Ошибка в коде после патча → откат (карточка 14).
  3. `could not connect to db` → база стартует дольше приложения: `docker compose restart <имя>`, когда `db` уже Up.
  4. `Address already in use` → карточка 20.
- ⚠️ Ловушка: `restart: unless-stopped` прячет проблему: контейнер «жив» по секундам. Смотри логи, а не только `ps`.
- 🔁 Почему `depends_on` не гарантирует, что база готова?

### 19. Упала база
- 👀 Признаки: в логах приложения `connection refused` к `db`; `docker compose ps` → `db Exited`.
- 🧯 Что делать:
  1. `docker compose logs --tail 50 db`.
  2. `docker compose up -d db` → когда Up, `docker compose restart <приложение>`.
  3. `No space left on device` → карточка 21. `Permission denied` на папку данных → не трогай сам, зови оргов.
- ⚠️ Ловушка: не удаляй `pgdata`/`data`, чтобы «начать с чистого листа». Это потеря всех флагов → CORRUPT.
- 🔁 В каком порядке поднимать базу и приложение?

### 20. Порт занят
- 👀 Признаки: `Bind for 0.0.0.0:5000 failed: port is already allocated` / `Address already in use`.
- 🧯 Что делать:
  1. `docker ps --format '{{.Names}}\t{{.Ports}}' | grep 5000`: чаще всего это старый контейнер того же сервиса.
  2. `ss -ltnp | grep :5000`: может, кто-то запустил `python3 app.py` руками для теста.
  3. Останови лишнее (тестовый процесс `Ctrl+C` / `kill <pid>`, старый контейнер `docker stop <имя>`) → `docker compose up -d`.
- ⚠️ Ловушка: не «решай» конфликт сменой внешнего порта в compose. Чекер придёт на старый → DOWN.
- 🔁 Почему нельзя просто перевесить сервис на 5001?

### 21. Кончилось место на диске
- 👀 Признаки: `No space left on device` в логах или сборке; база падает; сейв не создаётся.
- 🧯 Что делать:
  1. `df -h; docker system df`.
  2. Безопасно: `docker image prune` (только образы без имени `<none>`) и старые сейвы: `ls -t ~/backups | tail -n +30`, удаляй не нужные, `original` оставь.
  3. Логи контейнеров разрослись (их забивают атаки) → **уточнить у оргов** / с sudo: `truncate -s 0 $(docker inspect -f '{{.LogPath}}' <контейнер>)`.
- ⚠️ Ловушка: никакого `docker system prune -a --volumes`. Снесёт volumes (флаги) и образы, которые офлайн не скачать.
- 🔁 Чем `docker image prune` отличается от `docker system prune -a --volumes`?

### 22. Сервис тормозит, CPU/RAM на 100%
- 👀 Признаки: `curl` отвечает через 5+ секунд; MUMBLE/DOWN по таймауту; ноут/вулнбокс тупит.
- 🧯 Что делать:
  1. `docker stats --no-stream`: кто ест CPU/RAM. `free -h; uptime`.
  2. Контейнер убили за память? `docker inspect -f '{{.State.OOMKilled}}' <контейнер>`.
  3. Один сервис ест всё → `docker compose restart <имя>` (данные не теряются).
  4. Похоже на завал мусором (ДоС запрещён правилами) → скажи оргам и попроси защитника глянуть в Packmate, кто это.
- ⚠️ Ловушка: не ставь лимиты памяти/CPU в compose наугад. Сервис может начать падать на обычных запросах чекера.
- 🔁 Какой командой понять, что контейнер убили за память?

### 23. Сторож молчит, а сервис мёртв
- 👀 Признаки: в `healthcheck.sh` всё ✅, а на табло DOWN/MUMBLE.
- 🧯 Что делать:
  1. TCP-сервис (pwn) через `socat`: порт открыт всегда, даже если бинарник падает. Проверяй ответ: `echo | nc -w3 VB 31337 | head -c 200` (пусто = плохо).
  2. HTTP: сторож считает `4xx` живым. Проверь глазами: `curl -i http://VB:5000/<путь> | head`.
  3. Звука нет → проверь громкость и `command -v paplay spd-say`. Без звука смотри на экран сторожа.
  4. Табло проверяй каждый раунд: сторож видит только «жив/мёртв», флаги он не проверяет.
- ⚠️ Ловушка: «сторож зелёный» ≠ «чекер доволен». Главный источник правды: табло.
- 🔁 Почему pwn-сервис за `socat` выглядит живым для `nc -z`, даже когда сломан?

### 24. Сторож орёт: ВСЁ DOWN разом
- 👀 Признаки: все сервисы 💀 одновременно; SSH-сессия зависла.
- 🧯 Что делать:
  1. `ping -c3 VB` и `ip -br a`: туннель VPN на месте?
  2. VPN упал → переподключи (`nmcli connection up <имя>`).
  3. VPN цел, VB не пингуется → смотри табло: если там OK, сломалась только твоя связь; если DOWN, сразу к оргам.
  4. Долгие команды (`--build`) на вулнбоксе запускай в `tmux` / `screen` (если есть), чтобы обрыв SSH их не убил.
- ⚠️ Ловушка: не беги откатывать сервисы, когда всё упало разом. Это почти всегда сеть, а не код.
- 🔁 Почему «всё упало одновременно» почти всегда значит сеть?

### 25. Упали Packmate / ферма
- 👀 Признаки: атакующие кричат «ферма не сдаёт»; в Packmate не появляются новые потоки.
- 🧯 Что делать:
  1. `cd ~/ad-tools/<тулза> && docker compose ps` → `docker compose logs --tail 30`.
  2. `docker compose up -d` (без `--build`: образы из `docker load`).
  3. Packmate пуст после переподключения VPN → проверь, что в его `.env` правильный интерфейс (имя туннеля могло смениться) → `ip -br a`.
  4. Ферма: адрес сабмита и токен команды в её конфиге **уточнить у оргов** / у атакующих.
- ⚠️ Ловушка: тулзы второй приоритет. Если одновременно лежит наш сервис, сначала сервис (SLA множит очки).
- 🔁 Что чинить первым: упавшую ферму или DOWN нашего сервиса?

### 26. Вулнбокс перезагрузился
- 👀 Признаки: SSH отвалился и пустил заново; `uptime` показывает минуты; сервисы DOWN.
- 🧯 Что делать:
  1. `uptime; systemctl is-active docker; docker ps -a`.
  2. Поднять всё: `for d in ~/services/*/; do (cd "$d" && docker compose up -d); done`.
  3. Кто не поднялся сам, у того нет restart-политики: `docker inspect -f '{{.Name}} {{.HostConfig.RestartPolicy.Name}}' $(docker ps -aq)`.
  4. Проверь, что сейвы на месте: `ls ~/backups | wc -l`. Если вулнбокс пересоздали с нуля, бери копию с ноута (`~/vb-original`).
- ⚠️ Ловушка: не пересобирай всё подряд `--build`. Нужен просто `up -d`. Пересборка = лишние минуты DOWN и риск офлайн-ошибок.
- 🔁 Что сделает `docker compose up -d` с контейнером, у которого `restart: no`?

### 27. Кто-то из команды случайно что-то удалил
- 👀 Признаки: «ой», нет файла / папки, сервис DOWN.
- 🧯 Что делать:
  1. Удалили код → `ls -t ~/backups | grep <сервис> | head` → `./restore.sh <последний нормальный> ~/services/<сервис>`.
  2. Удалили всю папку сервиса → `scp -r ~/vb-original/<сервис> VB:~/services/` + накатить последний сейв патчей.
  3. Сделали `docker compose down` → просто `up -d` (без `-v` данные целы).
  4. Удалили данные → не вернёшь, держи сервис живым (карточка 13).
- ⚠️ Ловушка: не ищи виноватого во время игры. Сначала подними сервис, разбор после.
- 🔁 Чем `down` отличается от `down -v` для наших флагов?

### 28. Паника, суета, двое в одном сервисе
- 👀 Признаки: все кричат одновременно; два человека правят один файл; кто-то катит патч без сейва.
- 🧯 Что делать:
  1. Стоп на 10 секунд, выдох. Порядок: **сервис жив → патч → атака**.
  2. Правило из `backup-policy.md`: в чат «патчу X, бэкап есть». Один сервис = один человек.
  3. Пересборки на вулнбоксе делаешь ты (или с твоего «ок»). Тогда ты всегда знаешь, что менялось.
  4. Ведёшь короткий журнал: `время · сервис · что · сейв` (хотя бы в блокноте).
- ⚠️ Ловушка: не катить патч «пока все спорят». Нет сейва → нет патча.
- 🔁 Какие три слова должен написать в чат тот, кто патчит?

## 4️⃣ Между турами и в конце

### 29. Перерыв между турами
- 👀 Признаки: объявили конец 1-го тура.
- 🧯 Что делать:
  1. Сохрани текущее состояние кода себе: `scp -r VB:~/services ~/vb-after-tour1` (и на флешку).
  2. Перепиши журнал патчей начисто: что, когда, помогло или откатили.
  3. `df -h` на вулнбоксе, почисти старые сейвы (карточка 21). Заряди ноут.
  4. **Уточнить у оргов**: вулнбокс тот же или новый? Сервисы те же? Флаги и SLA сбрасываются? VPN переподключать?
- ⚠️ Ловушка: не правь сервисы в перерыве, если не уверен, что сеть закрыта и чекер стоит. Иначе можно поймать DOWN в первом раунде 2-го тура.
- 🔁 Какие 3 вопроса задать оргам в перерыве?

### 30. Конец игры
- 👀 Признаки: таймер на табло дошёл до конца, орги объявили конец.
- 🧯 Что делать:
  1. До официального конца ничего не `down` и не трогай: SLA считается до последнего раунда.
  2. После конца: сохрани себе журнал и, если правила разрешают, код сервисов (**уточнить у оргов**) для разбора.
  3. С ноутов оргов удали свои SSH-ключи и VPN-конфиги (`rm ~/.ssh/id_*`, `nmcli connection delete <имя>`).
  4. Вечером: 3 вещи «что сработало» и 3 «что улучшить» в скрипты.
- ⚠️ Ловушка: не уходи из сети за 5 минут до конца «потому что уже всё». Последние раунды тоже идут в SLA.
- 🔁 Почему нельзя гасить сервисы за пару минут до конца?

## 🧠 Мини-память (на одну ладонь)
- Всё DOWN разом → **сеть**. Один DOWN → **логи**. MUMBLE → **что меняли**. CORRUPT → **данные**.
- Нет сейва → нет патча. Сломал → откат без споров.
- Никогда: `down -v`, `system prune --volumes`, смена внешнего порта, откат базы.
- Сторож зелёный ≠ чекер доволен. Табло главнее.
